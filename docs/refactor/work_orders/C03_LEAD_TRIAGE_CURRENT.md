# C03 — 지팀장: 다음 회차 작업 설계·배정

**원칙:** 지팀장이 분석하고 결정한다. A/B는 C01/C02에 적힌 이번 회차의 코드 작업과 독립 검증을 순서대로 실행한다. A/B에게 RF·큐 전수 탐색, 작업 선정, D00 재독, 다음 작업 설계를 요구하지 않는다. D00은 **지팀장 자신이** 적용하여 보호·독점·수용 기준을 명령서에 필요한 만큼 구체화한다.

## 매회 수행

1. 정본 `integration/p1.5`의 최신 HEAD, Issue [#11](https://github.com/hbombheart1230-dotcom/agentra/issues/11)(A) · [#12](https://github.com/hbombheart1230-dotcom/agentra/issues/12)(B) · [#32](https://github.com/hbombheart1230-dotcom/agentra/issues/32)(RunLab)의 **신규 결과만** 확인한다. 각 브랜치 실제 SHA와 변경 코드·테스트를 확인한다. 기존 PASS는 반복 요구하지 않는다.
2. 지팀장 내부에서 미완료 작업, 실제 RF/파일 소유권, 목표 트리, caller·IO·State·예외·효과·보호 범위를 판정한다. **코드 결함 수정과 실질적인 구조 개선을 우선**하며 테스트만 추가하는 회차를 반복하지 않는다. C04/C05의 통합·완료 판정 책임은 침범하지 않는다.
3. `C01_CODEX_CURRENT.md`, `C02_CLAUDE_CURRENT.md`에 **바로 실행 가능한 다음 회차 명령**을 직접 작성한다. 각각 정확한 파일·함수, 확인된 결함 또는 목표 동작, 구체 수정/이동 방법과 제약, 필요한 정상·실패·최적화 테스트, **상대 브랜치의 검증할 고정 SHA·경로·기대 결과**, 커밋·푸시·Issue 보고를 적는다. 무리한 이동은 승인 전 지시하지 않는다.
4. 작업 명령은 실작업 2~4개와 명시적 검증으로 구성하되, **할당량·30분 종료 기준은 두지 않는다.** 하나 완료/부분 차단 시 다음 번호로 진행시키고, 실행 한도에 걸리면 실제 중단점부터 재개하도록 한다. 같은 검증의 무의미한 반복, RF 번호 나열, 과거 PASS 기록, 큐 스캔, D00 재독, '스스로 우선순위를 정하라' 같은 문구를 **C01/C02에 넣지 않는다**.
5. A/B 실행 중에는 이미 읽은 지시의 작업을 방해하지 않는다. 새 결과·차단·완료에 따라 명령서의 **이전 작업 본문을 교체**하되, 변화가 없으면 문서 커밋도 하지 않는다. 수정 후 원격 파일을 재조회해 문구·SHA 일치를 확인한다. 자신이 작성할 권한이 있는 문서만 수정한다.
6. 새 배정 또는 결함·차단 결정이 있으면 [Lead #36](https://github.com/hbombheart1230-dotcom/agentra/issues/36)에 A/B별 명령 파일·SHA·수정 이유·이어질 작업을 간략히 보고한다. C04는 LEAD 선별 통합/CI, C05는 원래 RF C1~C7·STATUS/DONE을 기존 예약대로 독립 수행한다.

**보호:** 계좌·브로커 주문/실거래, Step5C/UNKNOWN, UEF, RunLab 운영 상태, 동결 테스트, 사용자 데이터, 역할별 소유 코드 경계는 변경 승인 없이 건드리지 않는다. 상대 브랜치의 독립 검증은 정확 SOURCE_SHA의 **별도 임시 작업트리/복사본**에서만 수행하고 상대 소스는 수정·푸시하지 않는다. A/B의 변경은 각각 본인 브랜치의 허용된 소스·테스트에 한정한다.
