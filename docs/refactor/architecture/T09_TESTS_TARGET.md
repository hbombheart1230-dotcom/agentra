## 목표 구조(현재 테스트 발견 계약을 우선 유지)
```text
tests/
├── apps/
│   └── api/                        # API route/model/public profile
├── deploy/                         # compose/scheduler path contracts
├── fixtures/
│   ├── p1_5_*/                     # agent/role migration golden evidence
│   ├── uef9_synthetic/
│   ├── work_monitor/
│   └── work_reporter/
├── test_*.py                       # existing root tests DISCOVERY KEEP
└── 기타 공용 test helper          # explicit conftest/markers
```
새 `tests/unit|integration|e2e` 대규모 패키지로 이동을 강제하지 않는다. **현재 root test discovery 안정성이 우선**, 분리/이동할 경우 pytest, import, fixture scoping과 CI globs 모두 소비자 입증 필요.

## 종료 방식
1. **test conservation ledger:** 기존 파일/테스트 케이스 ID, 새 경로, fixture, marker, `-O`, 플랫폼, skip/xfail, expected exception, golden hash 보존.
2. 정상 및 최적화 Python, Windows/Linux, 실제 CLI/스케줄러 경계와 CI 선택 모드가 다르면 각각 그대로 보고.
3. 임시 pytest output은 세션별 격리, 성공 자동 삭제, 실패 제한 보존; repo 장기 누적 차단. 운영 DB·증거 원본 삭제 금지.
4. 테스트 기대값/CI oracle·allowlist·xfail/skip 수정 무승인 금지. READONLY peer가 소스 수정하거나 테스트를 억지 GREEN으로 만들어서는 안 됨.
5. 테스트 import/fixture namespace 충돌 또는 다른 RF 교차 consumer 문제는 cross-owner change로 지팀장 재배정.
